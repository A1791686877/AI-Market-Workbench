# BTC 情景区间分析框架（可重复运行）

> 本文件是**规则真源**：先于代码写出，代码 `app/outlook.py` 必须与本文的规则表一一对应。
> 版本：`btc-outlook-rules-v1`（2026-09-12 立）
> 性质：**确定性、零模型调用、零成本**的规则引擎，输出"三种路径的主观权重排序"，**不是概率、不是投资建议、不保证盈利**。
> 股票口径（`market="EQUITY"`）：**关闭四年减半周期规则**（`cycle_bottom_window` 记 0 分、`cycle_floor` 置空、
> `cycle_turn` 写"不适用"），只用确认日线；一键流程、结论登记与事后校验见
> `docs/phase-1/EQUITY-OUTLOOK-AND-REGISTRY.md`（`scripts\equity_outlook.py`）。

## 0. 为什么要这套东西

手工每次重算会得到互不一致的结论（前面几轮的教训）。本框架把"看什么、怎么算、什么情况改判"固定下来，任何一次行情来了只需一条命令：

```powershell
& .\.venv\Scripts\python.exe -B scripts\btc_outlook.py
```

产出：`reports/btc-outlook-<UTC时间>.json` + `reports/btc-outlook-<UTC时间>.md`，并打印结论。

## 1. 输入（全部来自项目原始数据，不引入新数据源）

| 输入 | 来源 | 要求 |
|---|---|---|
| BTC 日线（含周/月聚合） | `cache/market/okx-base-volume-v2/crypto-btcusdt-spot-1d.json` | 只用 `confirmed=true` 的柱 |
| BTC 4h / 1h / 15m | 同上，对应周期 | 同上 |
| （可选）资金费率/基差 | OKX 公共上下文接口 | 仅在 `--refresh` 时取；缺失不影响打分 |
| 派生：周线/月线 | `app.bar_builder.aggregate_bars`（只从已验证日线聚合） | 未收盘的周/月不出现在输入里 |

数据新鲜度、缺柱数、实际起止写入报告的 `data` 段；`history_complete=false` 会进 `limitations`。

## 2. 证据层（项目已有确定性函数）

| 证据 | 函数 |
|---|---|
| SMA / EMA / RSI / MACD / ATR / 布林 / ADX(+DI/−DI) / OBV / VWAP / 量价 | `app.indicators.compute_indicators` |
| 支撑阻力 + 趋势结构（HH/HL/LH/LL） | `compute_support_resistance_and_trend` |
| VPVR（VAL/POC/VAH + 位置） | `compute_vpvr` |
| FVG（创建时冻结 ATR、回补/有效性分离） | `compute_fvg` |
| SMA20/SMA50/SMA200/SMA20月/SMA200周 | 框架内直接对收盘序列计算（**注明为本框架的临时计算，不是项目指标**） |
| 四年周期 | 减半日 2024-04-19；收盘 ATH、距顶部天数、回撤、顶后最低点 |
| 期限同构样本 | 条件：距 ATH ≥240 天、回撤 −25%…−60%、收盘 > 上行 SMA200；统计未来 21/63/126 个交易日（中位/正比例/极值/样本数/簇数） |

## 3. 打分规则（v1）

### 3.1 结构分 structure（0…100，起始 40）

| 规则 | 分值 | 含义 |
|---|---:|---|
| 收盘 > 日 SMA200 | +12 / 不满足 −12 | 中期结构；**这是对称规则** |
| SMA200 较 20 日前上行 | +6 / 下行 −6 | 中期趋势方向 |
| 收盘 > 日 SMA50 | +6 / 不满足 −6 | 中期支撑 |
| 日线 +DI > −DI | +6 | 方向性动能 |
| 周线 +DI > −DI | +5 | 大周期动能 |
| 周线 MACD 柱 > 0 | +5 | 大周期动量 |
| 周线 MACD 柱较 8 周前改善 | +4 | 大周期拐点 |
| 距收盘 ATH 天数 ∈ [270,480] | +8 | 四年周期筑底窗口 |
| 同构样本 +63 日中位 > +5% | +6 | 历史类比 |
| 同构样本 +63 日正比例 > 0.60 | +4 | 历史类比 |
| 周线趋势状态 = DOWNTREND | −6 | 反向证据 |
| 月线趋势状态 = DOWNTREND | −8 | 反向证据 |
| 月线 MACD 柱 < 0 | −8 | 反向证据 |
| 月线 RSI < 50 | −4 | 反向证据 |
| 365 日收益 < −20% | −4 | 反向证据 |

### 3.2 动量分 momentum（0…100，起始 50；>50 偏多，<50 偏空）

| 规则 | 分值 |
|---|---:|
| 收盘 > 日 SMA20 | ±8 |
| 日线 MACD 柱 > 0 | ±8 |
| 日线 MACD 柱较 5 日前改善 | +6 / 0 |
| 7 日收益 > 0 | ±6 |
| 4h +DI > −DI | ±6 |
| 4h RSI > 50 | ±5 |
| 收盘 > 4h VPVR VAL | ±5 |
| 收盘 > 15m VPVR POC | ±4 |
| 1h 与 15m 趋势状态同时 = UPTREND | ±4 |
| 收盘 > 15m VPVR VAH | +3 / 0 |

> 缺失的输入（例如没有 4h 缓存）对应规则**跳过并记入 limitations**，不当作利空。

### 3.3 路径分与权重

```
A 先下后上 = 0.55 × structure + 0.45 × (100 − momentum)
B 直接上   = 0.60 × structure + 0.40 × momentum
C 破位     = 0.75 × (100 − structure) + 0.25 × (100 − momentum)
权重 = 三路径分归一化到 100%（四舍五入，保证和为 100）
```

设计含义：
- **结构在、动量弱 → A（回踩后再上）**：这就是"底部右侧第一轮回踩"的形态。
- **结构在、动量强 → B（直接上）**：日线收复 SMA20/前高后，A 的回踩步骤自动取消。
- **结构坏 → C（破位）**：一旦跌破 SMA200 或周线失守近低，A/B 让位。

### 3.4 关键位（全部由数据算出，不手工填）

| 名称 | 定义 |
|---|---|
| `confirm_reclaim` | 日 SMA20（日线收回即视为动量修复） |
| `confirm_breakout` | 最近 3 根日线的最高高点 |
| `early_kill_of_dip` | = `confirm_breakout`（日线收上它 → A 的"先下"作废，转 B） |
| `dip_zone` | 日线上距离现价最近的、仍有效且上沿 < 现价的看涨 FVG；没有则用 max(日 SMA50, 4h VPVR VAL) |
| `structural_support` | 日 SMA200（A 的主失效线） |
| `swing_low_20d` | 最近 20 根日线最低低点（预警线） |
| `targets` | [最近 30 根日线最高高点, 20 月线] |
| `cycle_floor` | 顶后最低低点（C 的最终目标） |

失效规则：**日线收盘 < `structural_support` → A 作废**；**周线收盘 < `swing_low_20d` 且两周收不回 → 转 C**；**月线收盘 < `cycle_floor` → 周期"还需深洗"剧本成立**。

## 4. 输出

`reports/btc-outlook-<UTC>.json`（机器可核）：规则版本、输入区间与缺柱、结构/动量分与逐条命中明细、三路径权重、`primary`、全部关键位、触发/失效条件、自动生成的结论文本、limitations。
`reports/btc-outlook-<UTC>.md`（人可读）：上面内容的表格版 + 结论。

## 5. 复现与验证

- 同一条命令、同一份缓存 → 逐字节相同结论（确定性）。
- 单元测试 `tests/test_outlook.py`：合成"结构在+动量弱 / 结构在+动量强 / 结构坏"三种序列，断言 primary 分别为 A/B/C，并断言关键位的大小关系与结论文本包含失效价。
- 规则版本变更必须改 `RULES_VERSION` 并同步更新本文档；历史报告保留，不覆盖。

## 6. 边界（必须随报告一起显示）

- 权重是**规则排序**，不是校准概率；没有样本外验证，不构成胜率。
- 场所级 OKX 数据、非全市场；历史 `history_complete=false`；清算/链上/ETF 流/宏观均缺失。
- **不是投资建议，不保证盈利。**

## 7. 执行结果（首次运行回填）

**实现**：`app/outlook.py`（规则引擎，130+ 行 Pydantic 报告模型）、`scripts/btc_outlook.py`（一条命令）、`tests/test_outlook.py`（7 项）。
**产物**：
- `reports/btc-outlook-20260912T130331Z.json` / `.md`（首次联网刷新运行）
- `reports/btc-outlook-20260912T130417Z.json` / `.md`（`--no-refresh` 离线复跑）
- 存档的手工判断：`docs/phase-1/BTC-OUTLOOK-2026-09-12.md`

**首次运行结论（BTC 现货，数据截止 2026-09-12 13:00 UTC，价格 77,223.4）**：

```
主判断：A 先下后上（回踩后再上）45%
一句话：先回 73405.4–76515 一次，再上 82285→88250.515；日线收盘破 70060.8385 认错。
结构分 76/100，动量分 26/100
确认：日线收盘 > 78621.165（SMA20）→ 再看 79896.3
回踩区：73405.4–76515（daily_BULLISH_FVG）
作废：日线收盘 < 70060.8385（SMA200）
周期：距减半 876 天，距顶部 340 天，回撤 -38.1%，顶后最低 57809.4
```

| 路径 | 分值 | 框架权重 | 我此前手工给的权重 | 差异说明 |
|---|---:|---:|---:|---|
| A 先下后上 | 75.1 | **45%** | 45% | 一致 |
| B 直接上 | 56.0 | 33% | 30% | 框架给 B 更高：4h +DI>−DI、价格站在 4h VPVR VAL 上方，规则层面对"直接上"给了分 |
| C 破位 | 36.5 | 22% | 25% | 框架给 C 更低：结构分 76 未破，破位只能靠动量拖累 |

> 结论：**框架复现了手工主判断（A 第一）**，权重差异 3 个百分点，来源已定位到具体规则；这说明"手工判断"没有引入规则之外的信息，差异可审计。

**确定性验证**：联网刷新（13:03:31）与离线复跑（13:04:17）两次运行，主判断、权重、关键位、分值完全一致（仅 `generated_at`/时间戳不同）。

**测试**：`tests/test_outlook.py` **7 passed**（合成"结构在+动量弱 / 结构在+动量强 / 结构坏"分别得到 A/B/C；权重和为 100；同一输入两次运行逐字节一致；缺失日内输入被跳过并记入 limitations 而非被当成利空）。

**已知未做**：规则参数未做样本外校准（本框架不产出胜率）；`--refresh` 需要网络，失败会降级为缓存数据并在 `data.fills` 里记录错误；本框架不写数据库、不调用模型。
