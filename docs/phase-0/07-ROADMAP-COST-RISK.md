状态：Phase 0 有条件通过，Phase 1 垂直切片实施中；估算日期 2026-09-05  
边界：只读基础版；以下不是收益承诺，也不是采购报价

## 1. 建议交付路线

工期按 2 名全职人员估算：1 名数据/后端/量化工程师，1 名全栈/AI/平台工程师；安全与金融数据授权由负责人兼职评审。单人开发不能简单按人数线性折算。

| 阶段 | 预计工期 | 主要交付 | 退出条件 |
|---|---:|---|---|
| 0. 需求与设计 | 已有条件通过并修正 | 本目录全部设计文档、生成式 Schema/OpenAPI、算法样例 | 正式 validator 和正反样例通过 |
| 1. 基础设施与数据 | 3–4 周 | E 盘目录/配置、数据库迁移、交易日历、Massive/Tiingo/SEC/Binance/CoinGecko/Coin Metrics 只读适配器、Bronze/Silver、数据质检 | 时间/来源/许可元数据完整；RTH 与 UTC 测试通过；无私有交易 API |
| 2. 指标、API 与页面 | 4–5 周 | Gold 指标层、扫描与自选、图表、REST/OpenAPI/MCP、基本面页面 | Golden Cases、因果性、拆股、DST、完整市场标记测试通过 |
| 3. AI 与审计 | 2–3 周 | Provider 抽象、快照、结构化输出、人工点击触发、成本限制、1h/4h/1d/1w 结果采集 | 相同快照可复现；未来结果无法进入提示词；失败不生成伪结论 |
| 4. 加固与基础版验收 | 2–3 周 | SBOM/依赖扫描、备份恢复、压力/故障注入、文档、发布包 | 风险门槛达标；恢复演练完成；许可签核 |

两人只读基础版合计约 **11–15 周**；经验丰富的单人全职开发约 **18–24 周**。这是工程估算，不含数据供应商合同谈判、法务答复、采购审批或外部服务故障造成的等待。

### 3.2 AI 成本模型

月成本不要写死为某个供应商价格：

`AI月成本 = 分析次数 × (平均输入token×输入单价 + 平均输出token×输出单价) + 重试/缓存损耗`。

规划样例：每月 1,000 次，每次 20k 输入+2k 输出，即 20M 输入、2M 输出。按 OpenAI 2026-07 官方公告中的 GPT-5.6 Terra USD 2/M 输入、USD 12/M 输出估算约 **USD 64/月**；同页 Luna USD 0.20/M、USD 1.20/M 约 **USD 6.4/月**。这只是便于量级判断的当前示例，模型、批处理、缓存命中和价格变化都会改变结果。系统必须先预估 token/金额，达到日/月预算则拒绝或等待人工提高预算。

## 4. 盈利能力评估协议

“覆盖更多股票”“回测胜率最高”都不是盈利证据。任何策略标签必须先冻结假设、数据版本和参数，报告：

- 样本外年化收益、总收益、每笔期望收益及置信区间；
- 盈亏比、胜率、交易次数、持有期和资金利用率；
- 最大回撤、回撤持续时间、尾部损失和容量；
- 真实费率、资金费率、点差、滑点、市场冲击和未成交模型；
- 牛/熊/震荡、高低波动与流动性压力环境的分层稳定性；
- 参数扰动、起止日期扰动、不同数据源和延迟条件的敏感性；
- 模拟实盘与回测的信号、成交和损益偏差。

必须阻断：未来函数、复权时间穿越、当日收盘前使用 EOD 基本面、幸存者偏差、用今天的成分股回测历史、训练/调参/测试集污染，以及为了历史结果反复挑参数。一次显著结果需控制多重检验/策略选择偏差，并保留失败实验。

## 5. 风险登记册

| 风险 | 级别 | 触发/影响 | 缓解与验收 |
|---|---|---|---|
| 数据许可与再分发误判 | 严重 | 个人/API 条款不覆盖公开产品 | 部署形态分级；逐源许可档案；商业上线前书面法务/供应商签核 |
| 延迟/市场范围误标 | 严重 | IEX 或单场所量被当作全市场 | `delay_class/market_scope/completeness` 强制字段；页面和 AI 同源展示；契约测试 |
| 未来数据泄漏 | 严重 | AI/回测读到未来价格、修订后财报或未确认枢轴 | cutoff 查询、PIT 成分/申报时间、outcome 独立角色、截断一致性测试 |
| 公司行动伪缺口 | 高 | 拆股触发 FVG/ATR/背离 | 原始+多种复权并存；行动窗口隔离；Golden Case |
| K 线时区/会话错误 | 高 | 盘前盘后混入、DST/半日市错位 | 交易所日历版本化；RTH 重采样；DST/半日市回归 |
| 交易所历史缺口 | 高 | 公共归档/API 不一致、OI/基差窗口短 | 自首日连续采集、校验和、序列连续性、源段隔离、不静默拼接 |
| LLM 幻觉/越权 | 高 | 猜数值、只给买卖、调用高风险工具 | LLM 只读冻结快照；JSON Schema；证据引用；无交易/账户 MCP 工具；输出校验失败即拒绝 |
| 模型供应商锁定 | 中高 | 升级困难、Schema 行为变化 | Provider 接口、契约测试、提示词和模型版本固定、可重放快照 |
| 成本失控 | 中高 | 扫描时误触模型、长上下文重试 | 仅点击调用；预算预检；缓存；幂等；日/月硬限额；成本日志 |
| 凭据泄漏 | 严重 | 日志、前端、Git 或异常栈包含密钥 | 基础版无需交易凭据；服务端秘密存储；结构化脱敏；secret scan；前端零密钥 |
| 依赖供应链 | 高 | 安装脚本、恶意更新、CVE | 固定哈希/版本、SBOM、OSV/pip-audit/npm audit/Trivy、隔离安装、最小依赖 |
| C 盘污染与磁盘耗尽 | 中高 | 默认 cache/home 写 C，原始数据增长 | 所有应用目录显式指向 E；启动前写路径检查；配额/保留策略/磁盘告警；备份演练 |
| 单机故障/数据库损坏 | 高 | 历史与审计不可用 | E 盘之外的加密备份目标由用户确认；WAL/快照；定期恢复演练和哈希核验 |
| 过拟合与虚假盈利 | 严重 | 历史好看、实盘失效 | 研究登记、OOS/滚动、成本/容量、参数敏感性、模拟实盘门槛；不承诺盈利 |

## 6. 上线门槛

只读基础版上线前必须同时满足：

- P0/P1 缺陷为 0；数据与指标验收全通过；
- 所有页面和 AI 结果显示来源、观测/有效时间、延迟、市场范围、完整性和缺失；
- 供应商条款、署名、缓存、内部使用/再分发边界有签核记录；
- 依赖锁文件、SBOM、高危漏洞处置和许可证扫描有证据；
- 备份、恢复、源故障切换、磁盘满、模型超时和无网络场景完成演练；
- 代码、数据、缓存、模型、临时文件和应用日志都在 E 盘；无主动 C 盘项目写入；
- 网络测试证明没有私有交易、账户、订单、转账或提币调用。
